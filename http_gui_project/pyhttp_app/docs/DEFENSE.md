# Ответы на вопросы для защиты (с привязкой к коду)

## HTTP
1. **HTTP/1.0 vs 1.1.** В 1.0 соединение по умолчанию закрывается после ответа, в 1.1 — keep-alive,
   есть chunked и `Host`. `Host` обязателен, потому что на одном IP/порту живут много виртуальных
   хостов — сервер выбирает сайт по нему (`Parser.validate_request` → 400 без Host).
2. **Content-Length** — длина тела в байтах. Без него (и без chunked) тело ответа читается до закрытия
   соединения (`MessageReader._read_until_close`), у запроса тела нет.
3. **chunked**: тело кусками `<размер hex>\r\n<данные>\r\n`, конец — кусок размера `0` и пустая строка
   (`_read_chunked`). Нужен, когда длина заранее неизвестна.
4. **GET vs POST на уровне протокола**: оба — просто метод в стартовой строке. GET по смыслу безопасен
   и идемпотентен, тела обычно нет; POST передаёт тело (`Content-Length`/`Content-Type`), не идемпотентен.
5. **keep-alive**: соединение остаётся открытым для следующих запросов. Сервер решает по `Connection` и
   версии (`_wants_keep_alive`), закрывает по `Connection: close` или idle-таймауту (5 с).
6. **301/302/307**: 301 — постоянный перенос, 302 — временный; для обоих браузеры меняют POST на GET.
   307/308 — повторить с тем же методом и телом. Клиент: `HttpClient.request` (303 → всегда GET).
7. **HEAD — не «GET без тела»**: заголовки (в т.ч. `Content-Length`) должны совпадать с GET, но тела нет,
   клиент не должен ждать тело; у GET и HEAD разная семантика кэширования/логики, сервер может не
   вычислять тело.
8. **Content-Type и charset** — тип данных и кодировка текста (`text/html; charset=utf-8`), без charset
   байты нельзя однозначно превратить в строку (`Response.charset`).

## Сокеты
9. **listen** переводит сокет в пассивный режим; **backlog** — длина очереди ещё не принятых соединений.
10. **accept** принимает входящее соединение и возвращает новый сокет; **connect** — инициирует исходящее.
11. **recv может вернуть меньше**: TCP — поток байт без границ сообщений. Читаем в цикле, пока не найдём
    `\r\n\r\n`, затем ровно `Content-Length` байт / chunked (`MessageReader`).
12. **SIGPIPE** — сигнал при записи в закрытый сокет. Python его игнорирует и бросает `BrokenPipeError`
    → мы превращаем в `HttpConnectionError` (`Socket.send_all`).
13. **close vs shutdown**: `close` освобождает дескриптор, `shutdown` закрывает направление передачи
    (и будит поток, висящий в `recv`) — используем при остановке сервера.
14. **SO_REUSEADDR** позволяет снова занять порт, пока старые соединения в TIME_WAIT
    (`TcpServer.start`) — без него перезапуск сервера даёт «Address already in use».

## Python и ООП
15. **Контекстный менеджер**: `__exit__` гарантирует `close()` даже при исключении; без него сокет
    «утечёт» до сборщика мусора (`with TcpClient(...).connect(...) as sock`).
16. **Router хранит Callable**: любой вызываемый объект/лямбда подходит, легко подменять в тестах
    (`router.route("GET", "/slow", _slow)`), нет `getattr` по строкам.
17. **Исключения в `__exit__`**: он не подавляет их (возвращает `None`), только закрывает ресурс.
18. **dataclass** даёт `__init__`, `__repr__`, `__eq__` без шаблонного кода — удобно сравнивать в тестах.
19. **isinstance** — только в `Serializer.serialize` (диспетчер); избежать можно `singledispatch` или
    вызывая `serialize_request`/`serialize_response` напрямую.
20. **Lock для логов**: несколько потоков пишут одновременно; `_notify_lock` сохраняет порядок и
    целостность записей, `_lock` защищает множества соединений/потоков.

## GUI и многопоточность
21. **Tk не потокобезопасен**: вызовы из фонового потока приводят к гонкам/зависаниям.
22. **root.after** ставит вызов в очередь событий главного потока — GUI обновляется там (`_poll`).
23. **queue.Queue** — потокобезопасный канал «поток → GUI» без ручных блокировок.
24. **Остановка без зависания на accept**: `accept` с таймаутом 0.2 с в цикле, проверка флага
    `_stop`, закрытие слушающего сокета (`HttpServer.stop`).
25. **Закрытие окна во время запроса**: поток-демон завершится вместе с процессом; `on_close` останавливает
    сервер, `after_cancel` снимает опрос очереди; результат запроса просто не будет показан.

## Безопасность
26. **Заголовок 1 МБ**: чтение прекращается после 8 КБ → `ParseError` → `400`, соединение закрывается
    (`MAX_HEADER_BYTES`, тест `test_huge_header_is_400`).
27. **Request smuggling**: фронтенд и бэкенд по-разному определяют границы запроса
    (CL vs TE), и «лишний» запрос проходит мимо проверок.
28. **CL + TE одновременно опасно** именно из-за этого; мы отклоняем такие сообщения (`400`).
29. **Path traversal**: `GET /../../etc/passwd`. Файлы мы не отдаём, маршруты — точные совпадения,
    поэтому ответ `404` (тест `test_path_traversal_is_just_404`); при раздаче файлов путь нужно
    нормализовать и проверять, что он внутри корня.
30. **strcpy-аналоги**: в Python нет переполнения буфера, но остаются неограниченные чтения и
    раздувание памяти — поэтому лимиты на размер заголовков, их число и тела.
